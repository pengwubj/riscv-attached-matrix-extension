[#ame:doc:func:ame_op_supported]
=== `ame_op_supported` (builtin)
Returns true if `src1 op src2 = dest` is a supported operation for the exact
datatype tuple supplied by the caller.  For a destination-as-source operation
implemented by `ame_op3`, the third value operand is the pre-instruction value
of the destination and is interpreted using `dest_dtype`.

[#norm:ame_op_supported_contract]#`ame_op_supported` returns false when any
required datatype is zero, when `op` is not implemented, when the datatype
classes do not satisfy the operation requirements, or when the implementation
does not support that operation/datatype combination.#

[#norm:ame_op_supported_defined_result]#If `ame_op_supported` returns true, a
subsequent `ame_op` or `ame_op3` call, as appropriate, with the same operation
and datatype tuple has the defined result described by the instruction and by
the operation tables below.#


|===
h| Return Type l| Boolean
h| Arguments   l| AmeOperation op, Bits<32> dest_dtype, Bits<32> src1_dtype, Bits<32> src2_dtype
|===

[#ame:doc:func:ame_scalar_op_supported]
=== `ame_scalar_op_supported`
Returns true when a data-scalar element-wise operation is supported after the
X-register scalar has been interpreted using `CSR[ame_scalar_dtype]` and
converted to the tensor operand datatype.

The scalar conversion is checked separately from the operation tuple.  The
operation itself therefore retains the ordinary AME contract in which both
data inputs use `tensor_dtype`.  This conversion precedes the operation for
all data-scalar forms, including bitwise operations; the converted value is
therefore interpreted in the same datatype domain as the tensor operand.

|===
h| Return Type l| Boolean
h| Arguments   l| AmeOperation op, Bits<32> dest_dtype, Bits<32> tensor_dtype
|===

[source,idl,subs="specialchars,macros"]
----
Bits<32> scalar_dtype = CSR[<<ame:doc:csr:ame_scalar_dtype,ame_scalar_dtype>>];
return <<ame:doc:func:ame_op_supported,ame_op_supported>>pass:[(]AmeOperation::CONV1D, tensor_dtype, scalar_dtype, scalar_dtype) &&
       <<ame:doc:func:ame_op_supported,ame_op_supported>>pass:[(]op, dest_dtype, tensor_dtype, tensor_dtype);
----

[#ame:doc:func:ame_scalar_data_value]
=== `ame_scalar_data_value`
Interprets an X-register bit pattern using `CSR[ame_scalar_dtype]` and
converts it to `target_dtype` using the common `CONV1D` semantics.  Callers
must first establish that `ame_scalar_op_supported` is true.  Only the low
`ame_dtype_val_to_size(scalar_dtype)` bits of the X-register value are used;
higher bits are ignored.

|===
h| Return Type l| Bits<AME_MAX_DTYPE_SIZE>
h| Arguments   l| Bits<32> target_dtype, Bits<AME_MAX_DTYPE_SIZE> raw_value
|===

[source,idl,subs="specialchars,macros"]
----
Bits<32> scalar_dtype = CSR[<<ame:doc:csr:ame_scalar_dtype,ame_scalar_dtype>>];
U32 scalar_element_size = <<ame:doc:func:ame_dtype_val_to_size,ame_dtype_val_to_size>>pass:[(]scalar_dtype);
return <<ame:doc:func:ame_op,ame_op>>pass:[(]AmeOperation::CONV1D, scalar_dtype, raw_value[scalar_element_size - 1:0], scalar_dtype, 0, target_dtype);
----

[#ame:doc:func:ame_dtype_is_packed]
=== `ame_dtype_is_packed`
Returns true if dtype_val is a packed datatype: its size in bits (bits 7:0) is
greater than zero and less than AME_UNIT_DATATYPE_SIZE.
Packed datatypes store pack_factor = AME_UNIT_DATATYPE_SIZE / size
squares per register and can be used directly as operands in compute instructions.


|===
h| Return Type l| Boolean
h| Arguments   l| Bits<32> dtype_val
|===

[subs="specialchars,macros"]
----
U32 size = dtype_val[7:0];
return size > 0 && size < AME_UNIT_DATATYPE_SIZE;
----

[#ame:doc:func:refresh_pending_interrupts]
=== `refresh_pending_interrupts`
refreshes the calculation of a pending interrupt

needs to be called after any state update that could change a pending interrupt. This includes:
   - CSR[mip]
   - CSR[mie]
   - CSR[mstatus].MIE
   - CSR[mstatus].SIE
   - CSR[vsstatus].SIE
   - CSR[mideleg]
   - CSR[sideleg]
   - CSR[hideleg]
   - CSR[hvip]
   - CSR[hgeip]
   - CSR[hgeie]
   - mode changes


|===
h| Return Type l| void
h| Arguments   l|
|===

[subs="specialchars,macros"]
----
Bits<MXLEN> pending_ints = CSR[<<ame:doc:csr:mip,CSR[mip]>>].sw_read() & $bits(CSR[<<ame:doc:csr:mie,CSR[mie]>>]);
if pass:[(]pending_ints == 0) {
  pending_and_enabled_interrupts = 0;
  return ;
}
Boolean HAS_MIDELEG = <<ame:doc:func:implemented_version?,implemented_version?>>pass:[(]ExtensionName::S, "<= 1.9.1") || (<<ame:doc:func:implemented_version?,implemented_version?>>pass:[(]ExtensionName::S, "> 1.9.1") && <<ame:doc:func:implemented_version?,implemented_version?>>pass:[(]ExtensionName::Sm, "> 1.9.1"));
Bits<MXLEN> mmode_enabled_ints = ((<<ame:doc:func:mode,mode>>pass:[(]) == PrivilegeMode::M) && (CSR[<<ame:doc:csr:mstatus,mstatus>>].<<ame:doc:csr_field:mstatus:MIE,MIE>> == 1'b0)) ? 0 : ($bits(CSR[<<ame:doc:csr:mie,CSR[mie]>>]) & (HAS_MIDELEG ? ~$bits(CSR[<<ame:doc:csr:mideleg,CSR[mideleg]>>]) : ~MXLEN'0));
Bits<MXLEN> mmode_pending_and_enabled = pending_ints & mmode_enabled_ints;
if pass:[(]mmode_pending_and_enabled != 0) {
  pending_and_enabled_interrupts = mmode_pending_and_enabled;
  return ;
}
if pass:[(]CSR[<<ame:doc:csr:misa,misa>>].<<ame:doc:csr_field:misa:S,S>> == 1'b1) {
  Bits<MXLEN> smode_enabled_ints = ((<<ame:doc:func:mode,mode>>pass:[(]) == PrivilegeMode::M) || (CSR[<<ame:doc:csr:mstatus,mstatus>>].<<ame:doc:csr_field:mstatus:SIE,SIE>> == 1'b0)) ? 0 : $bits(CSR[<<ame:doc:csr:mie,CSR[mie]>>]) & ($bits(CSR[<<ame:doc:csr:mideleg,CSR[mideleg]>>]));
  Bits<MXLEN> smode_pending_and_enabled = pending_ints & smode_enabled_ints;
  if pass:[(]smode_pending_and_enabled != 0) {
    pending_and_enabled_interrupts = smode_pending_and_enabled;
    return ;
  }
}
pending_and_enabled_interrupts = 0;

For standard integer arithmetic operations, the mathematical result shown in
the table is evaluated without intermediate truncation and then converted once
to the destination integer datatype.  A destination with `Saturation=1`
clamps an out-of-range result; a destination with `Saturation=0` retains the
low destination-width bits.  When a destination with `Saturation=1` clamps an
out-of-range result, the operation also sets
`CSR[<<ame:doc:csr:mxsat,mxsat>>].<<ame:doc:csr_field:mxsat:SAT,SAT>>`;
operations that do not saturate their output leave `mxsat` unchanged.
When the exact intermediate result of a standard integer tuple has fraction
bits below the LSB of the destination datatype (`HDIFF1D` and `MEAN1D`), the
result is rounded according to the destination datatype's *Rounding mode*
field (RNU/RNE/RDN/ROD, see <<datatypes>>) before the conversion above.
Custom datatype tuples may define their own conversion rule.

Standard floating-point tuples accrue the IEEE exception flags of each
element operation into `CSR[<<ame:doc:csr:mfflags,mfflags>>]`, using the same
flag definitions as the `fflags` CSR of the F extension.  AME operations do
not modify `fflags` itself.

Status-flag updates to `mfflags` and `mxsat` are not architecturally visible
per element.  They are accumulated in instruction-local staged state and are
OR-ed into the architectural CSRs only when the instruction completes and its
staged destination writes commit.  An instruction that raises a synchronous
exception commits no `mfflags` or `mxsat` update, following the same atomic
writeback rules as staged register writes.

Floating-point `CMPGE1D` and `CMPLT1D` use ordered IEEE comparisons: a NaN
operand makes the comparison false, and `-0` compares equal to `+0`.
The unselected result of `SELGE1D` and `SEL1D` is the destination datatype's
semantic zero, including its canonical zero sign.

For `SLL1D`, `SRA1D`, and `SRL1D`, the caller supplies the already-masked
unsigned shift amount defined by the corresponding instruction.  `ZERO1D`
returns the datatype's semantic zero; instructions must not assume that its
encoded representation is an all-zero bit pattern.  For `ROWID1D` and
`COLID1D`, the caller supplies the zero-based index as `src1`; the value is
represented exactly in the destination datatype, so no rounding or saturation
occurs.  Floating-point results
follow the rules below.

[#norm:ame_fp_special_values]
.Floating-point special values and accuracy
[cols="2,4,4",options="header"]
|===
| Operation | Required special-value result | Finite-result accuracy

| `MIN1D`, `REDUCEMINCOL1D`, `REDUCEMIN1D`
| If either operand is a NaN, return the destination datatype's canonical quiet
NaN.  Otherwise compare using the source datatype's numerical ordering.  A tie
between `-0` and `+0` returns `-0`.
| Exact selection of one operand.  Reduction instructions apply this binary
operation in ascending source-element order.

| `MAX1D`, `PREFIXMAXCOL1D`, `PREFIXMAX1D`, `REDUCEMAXCOL1D`, `REDUCEMAX1D`
| If either operand is a NaN, return the destination datatype's canonical quiet
NaN.  Otherwise compare using the source datatype's numerical ordering.  A tie
between `-0` and `+0` returns `+0`.
| Exact selection of one operand.  Prefix and reduction instructions apply this
binary operation in ascending source-element order.

| `SCATMAXCOL1D`, `SCATMAX1D`
| If either operand is a NaN, return the destination datatype's canonical quiet
NaN. Otherwise compare numerically after interpreting each operand in its own
datatype. A tie between `-0` and `+0` returns `+0`.
| Each selected destination is updated in ascending source-element order.

| `ADD1D`
| If either operand is a NaN, or if opposite-signed infinities are added, return
the destination datatype's canonical quiet NaN. Otherwise an infinity plus a
finite value, or two same-signed infinities, returns that infinity.
| The sum is correctly rounded once according to the destination datatype's
rounding mode.

| `SUB1D`
| If either operand is a NaN, or if same-signed infinities are subtracted,
return the destination datatype's canonical quiet NaN. Otherwise subtraction
of a finite value from an infinity, or an infinity from a finite value, returns
the mathematically signed infinity.
| The difference is correctly rounded once according to the destination
datatype's rounding mode.

| `ABS1D`
| A NaN returns the destination datatype's canonical quiet NaN. Either signed
zero returns `+0`, and either infinity returns `+infinity`.
| Exact for every representable finite result.

| `ABSDIFF1D`
| A NaN, or subtraction of two same-signed infinities, returns the destination
datatype's canonical quiet NaN. Any other infinite difference returns
`+infinity`.
| The absolute difference is correctly rounded once according to the
destination datatype's rounding mode.

| `MUL1D`, `NMUL1D`
| A NaN, or multiplication of zero by an infinity, returns the destination
datatype's canonical quiet NaN. Other infinite products follow the
mathematical sign; `NMUL1D` then negates that sign.
| The product is correctly rounded once according to the destination
datatype's rounding mode.

| `PREFIXADDCOL1D`, `PREFIXADD1D`, `REDUCEADDCOL1D`, `REDUCEADD1D`
| If either operand is a NaN, or if opposite-signed infinities are added, return
the destination datatype's canonical quiet NaN.  Otherwise an infinity plus a
finite value, or two same-signed infinities, returns that infinity.
| Each binary addition is correctly rounded according to the destination
datatype's rounding mode.  Prefix and reduction instructions apply additions
in ascending source-element order.

| `SCATADDCOL1D`, `SCATADD1D`
| The NaN and infinity results are the same as for `ADD1D`.
| Every contribution is correctly rounded to the destination datatype before
the next contribution to the same destination is applied; updates occur in
ascending source-element order.

| `SIN1D`, `COS1D`
| A NaN or either infinity returns the destination datatype's canonical quiet
NaN.  `sin(+/-0)` returns the same signed zero; `cos(+/-0)` returns `+1`.
| Implementation-defined.  An implementation must document its maximum error,
in ulp, for every supported operation and datatype tuple.

| `TANH1D`
| A NaN returns the destination datatype's canonical quiet NaN. `tanh(+/-0)`
returns the same signed zero and `tanh(+/-infinity)` returns `+/-1`.
| Implementation-defined, with the same documented maximum-error requirement.

| `EXP21D`
| A NaN returns the destination datatype's canonical quiet NaN.
`exp2(+infinity)` returns `+infinity`, `exp2(-infinity)` returns `+0`, and
`exp2(+/-0)` returns `+1`.
| Implementation-defined, with the same documented maximum-error requirement.

| `LOG21D`
| A NaN, a negative finite value, or `-infinity` returns the destination
datatype's canonical quiet NaN. `log2(+/-0)` returns `-infinity`, `log2(+infinity)` returns
`+infinity`, and `log2(1)` returns `+0`.
| Implementation-defined, with the same documented maximum-error requirement.

| `LDEXP1D`, `RDEXP1D`
| A NaN data operand returns the destination datatype's canonical quiet NaN.
A signed zero or signed infinity preserves its sign. Scaling overflow and
underflow are handled by destination conversion.
| The exact power-of-two-scaled result is rounded once according to the
destination datatype's rounding mode.

| `LOG2SUB1D`, `SUBLOG21D`
| NaN inputs and invalid infinity combinations return the destination
datatype's canonical quiet NaN. The `log2(abs(src1))` term follows the
`LOG21D` rules above.
| Implementation-defined. An implementation must document the maximum error
and whether the compound expression uses an intermediate rounding.

| `REC1D`
| A NaN returns the destination datatype's canonical quiet NaN. `1/(+/-0)`
returns the correspondingly signed infinity, and `1/(+/-infinity)` returns the
correspondingly signed zero.
| Implementation-defined, with the same documented maximum-error requirement.

| `RSQRT1D`
| A NaN, `-infinity`, or a negative finite value other than `-0` returns the destination
datatype's canonical quiet NaN. `rsqrt(+0)` returns `+infinity`, `rsqrt(-0)`
returns `-infinity`, and `rsqrt(+infinity)` returns `+0`.
| Implementation-defined, with the same documented maximum-error requirement.

| `SQRT1D`
| A NaN, `-infinity`, or a negative finite value other than `-0` returns the destination
datatype's canonical quiet NaN. `sqrt(+/-0)` preserves the signed zero and
`sqrt(+infinity)` returns `+infinity`.
| Correctly rounded according to the destination datatype's rounding mode.

| `FRINTM1D`, `FRINTN1D`, `FRINTP1D`, `FRINTZ1D`
| A NaN returns the destination datatype's canonical quiet NaN.  An infinity is
unchanged and a zero preserves its sign.
| Exact when the integral value is representable.  The operation-specific
rounding direction overrides the destination datatype's rounding-mode field.
|===

For these operations, a signaling NaN is treated as a NaN and the result is
quieted.  If a mathematical result is infinite but the destination datatype
does not encode infinity, the result saturates to that datatype's signed
minimum or maximum, as appropriate.  An operation/datatype tuple that cannot
represent a required NaN result is unsupported.

AME defines no floating-point exception flags.  Once `ame_op_supported` has
accepted a tuple, the special cases above are normal data results: they neither
set `amestatus.UN` nor raise an exception.  `amestatus.UN` reports only an
unsupported operation/datatype tuple.

=== `ame_op3` (builtin)
Returns the result of a destination-as-source operation with two explicit
source values and the pre-instruction destination value.  `current_value` is
interpreted using `dest_dtype`.

`ame_op3` is the three-value counterpart of `ame_op` and is the common semantic
boundary for datatype interpretation, conversion, rounding, saturation,
floating-point exceptional values, and custom datatype behavior.  It is called
only for a tuple for which `ame_op_supported` returned true.  The low
`sizeof(dest_dtype)` bits contain the result; higher bits are undefined.

|===
h| Return Type l| Bits<AME_MAX_DTYPE_SIZE>
h| Arguments   l| AmeOperation op, Bits<32> src1_dtype, Bits<AME_MAX_DTYPE_SIZE> src1_value, Bits<32> src2_dtype, Bits<AME_MAX_DTYPE_SIZE> src2_value, Bits<AME_MAX_DTYPE_SIZE> current_value, Bits<32> dest_dtype
|===

.Destination-as-source operation semantics
[cols="2,3,3",options="header"]
|===
| `AmeOperation` | Mathematical result before destination conversion | Required operand class

| `MUXGE1D`
| `src2` when the sign bit of `src1` is clear; otherwise `current`
| A predicate datatype with a defined sign bit; identical `src2` and destination datatypes

| `MUXLT1D`
| `src2` when the sign bit of `src1` is set; otherwise `current`
| A predicate datatype with a defined sign bit; identical `src2` and destination datatypes

| `LDEXPACC1D`
| `current + src1 * 2^src2`
| Numeric data and destination datatypes; integer exponent datatype

| `RDEXPACC1D`
| `current + src1 * 2^(-src2)`
| Numeric data and destination datatypes; integer exponent datatype

| `MULACC1D`
| `current + src1 * src2`
| Supported numeric source and destination datatypes

| `MULNACC1D`
| `current - src1 * src2`
| Supported numeric source and destination datatypes

| `MULADD1D`
| `src1 + src2 * current`
| Supported numeric source and destination datatypes

| `MULSUB1D`
| `src1 - src2 * current`
| Supported numeric source and destination datatypes
|===

For `MUXGE1D` and `MUXLT1D`, an unselected `current` value is preserved bit
exactly in its low `sizeof(dest_dtype)` bits.  For every arithmetic operation
above, the complete mathematical expression is evaluated without an
intermediate destination conversion and is converted to `dest_dtype` once.
Thus `MULADD1D` and `MULSUB1D` have fused multiply-add/subtract semantics.

For floating-point arithmetic, any NaN input produces the destination
datatype's canonical quiet NaN.  Invalid infinite forms, including zero times
infinity and addition of opposite-signed infinities, also produce that NaN.
Other infinities follow the mathematical expression.  A finite result is
rounded once according to the destination datatype's rounding mode.  These
results follow the same no-floating-point-exception-flags rule as `ame_op`.
